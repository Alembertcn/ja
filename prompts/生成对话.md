# 提示词：生成对话（输出结构化 JSON）

用途：生成听力口语向的对话，产物落到 `content/articles/<id>.json`。与[生成课文](./生成课文.md)共用同一份数据契约，区别是 `type` 为 `dialogue`，每行必须带 `speaker`。

---

```text
请按仓库的课文数据契约生成一段日语对话。

【契约】
严格遵守 content/schema/article.schema.json。只输出一个 JSON 对象，不要任何解释文字。

【本次参数】
- 计划文件：docs/plan/N2学习计划_2027年7月.md
- id：{W15-denwa-taiou}
- 周次 week：{15}    阶段 stage：{P1}    等级 level：{N3}
- type：dialogue
- 场景 scene：{职场：接客户电话并转达留言}
- 说话人：{田中（公司职员）、客户（山田）}
- 必须覆盖语法模块 grammarModules：{G1-15,G2-F01,G2-H12}
- 词汇主题 vocabTopic：{V1-D}
- 回合数：{8–12} 个回合

【逐行要求】
lines 每个元素是一句台词：
- speaker：说话人名字，必填
- id：l01、l02… 两位数顺序编号
- jp / reading / romaji / furigana / zh / grammar / vocab / isSentenceEnd 的要求与「生成课文」完全一致
- furigana 的 start / len 是汉字串在 jp 中的字符下标与长度，从 0 开始数，标点也算一个字符，务必逐字核对

【内容要求】
- 口语自然，符合该场景的敬语层级（对客户用谦让语，对同事用ですます）
- 每个回合不要过长，一句一行，便于逐句跟读
- grammar 里除了目标语法，也要解释敬语的尊敬／谦让归属
- 遇到寒暄或固定表达，在 grammar 里说明使用场合与禁忌

【输出】
只输出 JSON 本体。生成后自检：furigana 下标正确、speaker 每行都有、JSON 可解析。
```

---

## 生成之后

```bash
python tools/build.py --check
```
